2026-10-28 最终全量测试为 **2119 passed、14 skipped、0 failed**，双前端构建、配置检查及相关 Python 静态检查通过。真实 DeepSeek 小样本 A/B 中，关键事实保留与下一轮遵循均由旧策略的 **15/28 提升至 28/28**，同时摘要输入量约为旧策略的 **4.48 倍**、摘要耗时约为 **3.93 倍**。这些结果不代表生产会话无损压缩或普遍质量保证。

## 2. 问题与关键改造

旧项目显式设置 `trim_tokens_to_summarize=max(4000, int(model_max * 0.02))`。在 131072 窗口下，待摘要旧历史会先被裁成末尾约 4000 tokens，早期约束可能在进入摘要模型前丢失。单纯取消裁剪又可能使完整旧历史超过单次摘要请求容量。

当前通过 DeepAgents 公开 `summarizer` 接口接入 `HistorySummarizer`，显式设置 `trim_tokens_to_summarize=None`，处理流程为：

```text
待摘要旧历史 → 按预算分块 → 各块事实抽取与摘要 → 逐层分组合并
           → 最终摘要语义覆盖检查 → 摘要事件 + 保留的近期消息
```

| 改造 | 当前行为 |
| --- | --- |
| 分块与合并 | 每次请求重新核算完整提示词预算；工具调用与结果尽量同块，超长消息切片保留角色、消息 ID、调用 ID 和偏移；摘要前保留待摘要旧工具参数。 |
| 事实覆盖 | 抽取目标、约束、修正、路径、事实和待办，判定 `preserved/missing/uncertain`；缺失、不确定或空清单明确告警，**不自动补写**。 |
| 请求前保护 | preflight 计入系统提示、消息、工具及后续 memory/skills 提示；最终 guard 再检查实际请求，无法缩至预算则拒发。 |
| 输出保护 | 设置摘要输出上限，拒绝空白、已知截断、超限、非法审计结果及无法收敛的合并；失败不提交新摘要事件。同步、异步共用处理计划。 |
| 手动持久化 | `POST /agent/sessions/{session_id}/context/compact` 使用会话锁和同一摘要器，保存并回读校验 checkpoint；后续聊天复用摘要事件，原始消息仍保留。 |
| 观测与留痕 | 记录模式、块数、内部调用数、合并层数、阶段 token、耗时、状态与 provider usage；可选 trace 保存中间产物及父子关系，调用状态独立隔离。 |

DeepAgents 继续负责历史划分、归档与摘要事件应用。部分窗口、快照和 checkpoint 适配仍依赖当前框架版本的私有钩子，升级时需回归验证。

## 3. 预算与配置重点

配置位于 `summarization`，并同步到 schema、模板和图缓存指纹。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | true | 正常自动摘要与工具参数截断开关；关闭后仍保留配置窗口保护。 |
| `compression_threshold` / `compression_target` | 0.8 / 0.1 | 自动触发比例 / 近期消息保留比例。 |
| `input_fraction` | 0.55 | 摘要完整提示词的输入预算比例。 |
| `max_output_tokens` | null | 默认由有效窗口推导为 `min(4096, int(W * 0.2))`；输入与输出预算合计不得超过窗口的 90%。 |
| `coverage_enabled` | true | 生产装配启用事实抽取与语义覆盖检查，会增加模型调用。 |
| `trace_enabled` / `snapshot_enabled` | false / true | 中间摘要留痕 / 自动压缩前后正文快照，两个开关独立。 |

摘要有效窗口 `W` 取配置窗口与已知模型 profile 输入上限的较小值。主模型配置输入预算为 `95% × 配置窗口 − 已配置输出预留`，再与框架 provider 预算取较小值；它与摘要输入预算分开计算。

计数使用近似 token，预算保护不能保证供应商永不超窗。要关闭两类正文留存，须同时关闭 `trace_enabled` 和 `snapshot_enabled`；普通日志及 checkpoint 的公开报告仅保留统计和白名单字段。

## 5. 已知边界与后续重点

- **语义仍可能有损**：事实抽取与覆盖判分都可能遗漏或误判，告警不等于修复。真实评估使用固定合成历史，未重放此前 498 条生产消息；judge 为独立调用，仍有同模型偏差。
- **质量提升伴随开销**：A/B 当前摘要累计输入 84543 tokens、耗时 78.57s；旧策略为 18852 tokens、19.98s。未提供单价，费用金额保持 null。`summary_calls` 包含抽取、摘要、合并与审计等所有内部调用。
- **预算需继续校准**：样本最大输入低估 23.49%。本次使用 1024 输出预留，不能证明默认 55% 输入比例与所有输出预留组合均安全；也未完成生产主模型完整请求与 provider usage 的端到端对比。
- **手动实测有边界**：真实供应商只执行摘要；次轮使用 Recorder 验证持久化接线，未在该实验中验证真实主模型语义质量。

后续重点是扩大真实模型与生产代表性样本、重复 A/B 和人工抽检，并校准完整主模型请求的预算误差与成本。
