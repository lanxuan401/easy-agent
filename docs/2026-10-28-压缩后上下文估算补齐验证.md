# 压缩后上下文估算补齐验证

日期：2026-10-28。

> 追查更新：前次补齐没有解决线上跳变。第 1–3 节保留前次验证范围；本次原因、修复和证据见第 4 节。

## 1. 问题与修复

用户反馈上下文占用压缩后由约 79% 降至 13%，仅发送“你好”便升至约 38%。原手动压缩估算遗漏工具定义及运行时技能、记忆等提示，现已补齐；未取得截图对应请求明细，不能把全部 25 个百分点归因于漏计。

补齐内容包括编译图的工具 schema、文件系统能力过滤与路由提示，以及当前技能、会话/长期记忆和启用时的上传清单。切换摘要模型时仍从原聊天代理读取运行时装配。读取仅用于局部估算，不修改 checkpoint 缓存，不执行聊天模型或工具。

压缩成功及“当前无需压缩”均刷新估算，不改写真实 usage 或计费用量。不复用上一轮临时 `turn_context`：下一轮的检索、附件和技能选择尚未发生。本次未引入 provider 锚点或持续事件投影，也未修改自动压缩阈值的计量方式。

## 3. 使用与边界

仍采用 `count_tokens_approximately` 字符启发式。中文分词、供应商序列化、多模态、动态解锁工具及下一轮新增内容仍会造成偏差；工具估算以编译图可见的静态工具为基础。框架私有访问集中在手动压缩适配层，升级后需回归。

本次功能验证未重启服务或操作用户在线会话。后端加载新代码后，再次压缩（含跳过）会刷新估算，历史旧估算不会自动重算。实际 13% → 38% 的改善幅度仍需同会话在线复测并取得 provider usage。

实现入口：[manual_compaction.py](/Users/lulongfei/Desktop/easy-agent/easy_agent/agent/manual_compaction.py)、[context_compaction.py](/Users/lulongfei/Desktop/easy-agent/easy_agent/services/context_compaction.py)。整体交互见 [手动压缩验收报告](/Users/lulongfei/Desktop/easy-agent/docs/2026-10-27-指令菜单与手动压缩验收报告.md)。

## 4. 用户复测后追查：估算口径切换仍导致跳变

用户再次反馈：压缩后约 20%，问一句变成约 40%，随后正常递增。只读检查本地进程、SQLite checkpoint 和业务库，确认两项问题：

1. 后端进程从 11:43 启动后未重启，也未开启 `--reload`；前次估算补齐文件于 15:16 更新，运行进程没有加载它。16:28 的压缩记录为 18,165 token，下一句“你好”的 provider input 为 29,124，随后“你是谁”为 29,339（窗口 65,536）。
2. 即使请求内容补齐，默认 `count_tokens_approximately` 仍按约 4 字符/token 计数，对中文和供应商序列化可能低估。压缩后显示近似值，下一轮改用真实 input usage，形成一次明显跳变。此前 Recorder 的“同算法相差 5 token”不能证明与 provider 用量接近。

本次增加按会话持久化的 `context_usage_anchor`：在最终请求进入模型时记录同一近似算法的输入估算，返回后配对该请求的 provider `input_tokens`。手动压缩展示按 `实际输入 / 同请求估算` 校准压缩前后数值。采样不写入消息、计费用量或共享中间件实例，不修改自动压缩阈值和预算算法；摘要模型调用不覆盖聊天请求样本。样本按模型类型、模型名和端点指纹匹配，切换模型不借用旧比例。

旧 checkpoint 无样本时，仅在最近聊天响应明确标记同一模型时，用原摘要事件和响应之前的历史重建输入进行校准，并保存这份样本，避免重复压缩时用新摘要重算旧请求。无法匹配时回退普通估算。报告保留 `raw_context_tokens`、`estimation_method` 和 `calibration_source` 供排查，仍明确属于估算。

只读重建 16:28 那次压缩的前后 checkpoint，使用本地已保存的请求快照提示与工具定义，得到以下对照（未调用在线模型、未改用户会话）：

| 项目 | tokens | 占 65,536 |
| --- | ---: | ---: |
| 原压缩记录 | 18,165 | 27.72% |
| 使用快照提示与工具的未校准重建 | 15,294 | 23.34% |
| 重建校准后 | 28,553 | 43.57% |
| 下一句 provider 真实 input | 29,124 | 44.44% |

校准参考请求的 provider input 为 42,006，重建近似值为 22,500；故 `ceil(15,294 × 42,006 / 22,500) = 28,553`。该快照来自更早的自动压缩边界，不能复原当时所有动态提示与记忆；相差 571 token（约 0.87 个百分点）是离线重建结果，不能当作新版完整在线重放。中文占比、多模态、提示/工具大幅变化仍可能改变比例。

新增 [test_context_estimation.py](/Users/lulongfei/Desktop/easy-agent/tests/agent/test_context_estimation.py)，使用真实 DeepAgents 图与官方 SQLite saver，模拟 provider 输入为原近似值的 1、2、3 倍，覆盖同步/异步调用、手动压缩后短句、跳过刷新、SQLite 重开、旧 checkpoint 连续压缩、共享图的会话隔离和模型切换。模拟用量用于验证口径切换行为，不代表真实模型分词精度。

验证：后端全量在本次初版实现上 **2,130 passed、14 skipped**；随后补强旧样本持久化与摘要模型切换隔离，最终版本专项 **73 passed**（其中校准测试 **16 passed**）。Ruff 与 diff 空白检查通过。前端未修改，未构建。
