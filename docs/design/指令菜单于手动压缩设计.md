# 指令菜单与手动压缩设计

日期：2026-10-26  
状态：已实施（2026-10-27）；实现与验证记录见 [验收报告](../2026-10-27-指令菜单与手动压缩验收报告.md)

## 1. 需求

在当前输入框的 `/` 技能选择面板中，增加“指令”分组，分组下增加“压缩 compact”。用户点击后，立即对当前会话执行一次上下文压缩。

界面参考：[目标菜单](../assets/context-compression/command-menu-reference.png)、[当前菜单](../assets/context-compression/current-skill-menu.png)。

## 2. 交互

输入 `/` 后展示：

```text
指令与技能                         ↑↓ 选择 · Enter 确认 · Esc 关闭

指令
  压缩 compact     压缩较早对话，保留近期内容          /compact

技能
  pdf              …                                /pdf
  skill-creator    …                                /skill-creator
```

- “指令”排在“技能”前；原技能选择功能继续使用。
- 输入 `/com` 或 `/压缩` 可筛选到压缩操作。
- 点击“压缩”，或用方向键选中后按 Enter，立即执行，无须再点发送。
- 选中后关闭面板，只移除本次 `/查询词`，保留其他草稿和附件。
- 执行期间显示“正在压缩...”，禁用重复压缩和本会话发送。
- 成功提示“已压缩”；没有可压缩的旧内容时提示“当前无需压缩”；失败时提示错误并允许重试。
- 新会话无历史、正在生成或等待审批时，压缩项置灰并显示原因。

指令是操作按钮，不作为技能标签插入，也不发送成一条聊天消息。菜单加载技能失败时，压缩操作仍可展示。键盘确认需避开中文输入法组词状态。

## 3. 执行流程

```text
点击压缩
  → 前端调用手动压缩接口
  → 后端读取当前会话上下文
  → 复用现有摘要能力执行压缩
  → 保存摘要状态到当前会话 checkpoint
  → 返回结果，前端结束加载并提示
```

关键点：手动操作直接触发压缩，不等待自动压缩阈值；摘要模型、提示词和近期消息保留策略沿用现有配置。压缩后，下一轮对话读取新的摘要状态。

原聊天记录仍可查看。执行过程只生成摘要，不额外调用主模型回答，也不追加普通用户或助手消息。

## 4. 接口

新增 `POST /agent/sessions/{session_id}/context/compact`。

前端提交当前选择的模型 key；后端通过 JWT 和现有会话归属校验确定用户与会话。

接口等待本次压缩完成后返回 JSON：

```json
{
  "session_id": "当前会话ID",
  "status": "compacted",
  "message": "已压缩"
}
```

没有可压缩内容时返回 `status: "skipped"`；失败使用项目现有错误响应。前端为这次摘要请求设置合适的超时，等待期间展示加载状态。

本功能采用一次请求完成的方式，不另设任务表、任务查询接口或轮询流程。

## 5. 后端接入要点

新增一个小的会话压缩服务，集中处理读取上下文、调用摘要、保存 checkpoint。框架相关操作放在摘要适配层，API 只负责鉴权与调用。

### 5.1 读取 → 摘要 → 保存

以下是后续实现参考，尚未接入业务接口。前提是已校验会话归属、进入与聊天共用的会话互斥范围，并确认当前 thread 没有生成任务或待审批任务。

**读取当前会话。** 会话级模式下，`thread_id = session_id`。沿用 [session_thread.py](../../easy_agent/services/session_thread.py) 中 `plan_turn()` 的读取方式，从 checkpoint 取 `messages` 和旧摘要事件；聊天记录表用于界面展示，不能直接当成压缩后的有效上下文。

```python
graph = agent.agent
state = await graph.aget_state(build_run_config(agent, session_id))
values = state.values or {}
raw_messages = list(values.get("messages") or [])
previous_event = values.get("_summarization_event")
```

**复用摘要能力。** 通过 [summarization.py](../../easy_agent/agent/summarization.py) 的 `build_summarization_middleware(config, model, backend)` 创建本次操作使用的摘要实例 `summ`。`model` 使用当前选择的模型，`backend` 需绑定当前用户和会话；共享 `ContextBackend` 可通过 `resolve(session_context)` 获取具体实例，不能依赖 HTTP 请求中不存在的图运行上下文。

```python
summ = build_summarization_middleware(config, model, backend)

# 已压缩过时，实际上下文是“旧摘要 + 尚未摘要的原始消息”
effective = summ._apply_event_to_messages(raw_messages, previous_event)
cutoff = summ._determine_cutoff_index(effective)
if cutoff <= 0:
    return {"status": "skipped"}

older, recent = summ._partition_messages(effective, cutoff)
prepared, failed_media = await summ._aoffload_inline_media(backend, older)
history_id = summ._get_session_id(values)
file_path = await summ._aoffload_to_backend(backend, prepared, history_id)
summary = await summ._acreate_summary(prepared)
```

`_determine_cutoff_index()` 根据现有 `keep` 配置选择保留范围，并保护工具调用与结果配对；`_acreate_summary()` 将旧消息填入现有摘要提示词，调用摘要模型返回文本。直接调用摘要方法，跳过自动触发阈值判断；不要调用整个 `awrap_model_call()`，因为它还会继续执行主模型回答。

构造实例会沿用当前摘要参数，包括 `trim = max(4000, int(model_max * 0.02))`。若采用“不预先裁剪摘要输入”的策略，要在本次实例的构造参数中显式传 `trim_tokens_to_summarize=None`；省略参数不代表取消限制。不得修改共享中间件的参数来临时触发压缩。长输入预算及框架溢出重试行为见[上下文压缩说明](../上下文压缩.md)。

**写回当前 checkpoint。** 保存摘要事件及历史归档 ID，保留原始 `messages`：

```python
event = {
    "cutoff_index": summ._compute_state_cutoff(previous_event, cutoff),
    "summary_message": summ._build_new_messages_with_path(summary, file_path)[0],
    "file_path": file_path,
}
updated_config = await graph.aupdate_state(
    state.config,
    {
        "_summarization_event": event,
        "_summarization_session_id": history_id,
    },
    as_node=terminal_node,
)
saved = await graph.aget_state(updated_config)
# 确认摘要事件已保存，且 saved.next 为空后，返回 compacted。
```

`aupdate_state()` 通过图已配置的 checkpointer 创建新 checkpoint，无须直接操作 checkpoint 数据库。`history_id` 仅用于摘要历史归档文件命名，与定位会话的 `thread_id` 不是同一个概念。

`terminal_node` 必须由适配层根据实际编译图确定为结束节点，避免更新状态后留下模型或工具待执行任务。当前离线验证图为 `_ParentNotifierMiddleware.after_agent`；实现时不能把这个名字当作所有装配方式都适用的常量，也不能直接用 `__end__` 代替。

例如原始消息有 100 条，事件的 `cutoff_index=80`，下一轮现有摘要中间件会读取“摘要 + `raw_messages[80:]` + 新消息”。再次压缩时，`_compute_state_cutoff()` 将有效上下文里的位置换算回原始消息位置，避免重复计算旧摘要。

### 5.2 实现边界

以下属于首版需要处理的可靠性边界，多数是在现有流程中增加判断和错误处理：

| 边界 | 实现方式 |
| --- | --- |
| 聊天与压缩不能同时写入 | 聊天、压缩统一使用按 `session_id` 划分的锁，从读取到写回都在锁内。后端在锁内检查生成和审批状态，忙碌时拒绝压缩；前端同步禁用操作。已有互斥机制则复用，否则补齐两个入口，不能只给压缩接口加锁。 |
| 保留近期消息、保护工具配对 | 复用 `_determine_cutoff_index()` 和 `_partition_messages()` 选择安全分割位置；没有可摘要的旧消息时返回 `skipped`。 |
| 摘要必须保存到当前会话 | 摘要成功后，将内容、覆盖位置等写入 `_summarization_event`，通过 `aupdate_state()` 创建新 checkpoint；校验保存结果和无待执行任务后才返回 `compacted`，原始消息保留。 |
| 摘要失败不覆盖旧状态 | 先在局部变量中生成摘要；摘要调用失败或输入预算检查不通过时返回错误，不提交新摘要事件。checkpoint 写入失败也不能返回成功。 |
| 旧 thread 模式不支持 | 后端确认当前使用会话级 thread；每消息独立 thread 的旧模式返回不支持，前端置灰，避免下一轮重建历史后压缩结果失效。 |
| 框架私有方法兼容 | 将 `_` 方法集中封装在摘要适配模块，用当前依赖版本的真实建图测试覆盖“摘要 → 保存 → 下一轮复用”，升级依赖时验证；读写状态使用公开的 `aget_state()`、`aupdate_state()`。 |
| 归档或媒体处理失败 | 首版采用失败即终止的策略，提示重试，不提交新摘要事件。显式检查 `file_path is None`、`failed_media > 0` 等返回结果，不能仅捕获异常，避免摘要引用无法访问的历史或丢失的媒体。 |

第 5.1 节代码是核心流程示意，实现时需要补上表中的检查。

手动压缩的 before/after 快照属于排查工具，首版可以不做，不影响摘要持久化和下一轮复用。直接调用摘要方法不会自动生成现有包装器中的快照；后续需要时显式接入快照保存逻辑。

2026-10-27 截图反馈后调整：状态以 `compact · 正在压缩...` / `compact · 已压缩` 展示在消息流内，与正文列对齐。完成记录保存在 checkpoint 独立的 `context_compactions` 字段，不增加普通聊天消息；会话详情与历史接口将记录投影到对应消息之后，刷新仍可恢复。

压缩接口成功或跳过时增加 `compaction` 字段，返回压缩前后 token 估算、模型窗口和消息位置。占用环立即使用保存后“摘要 + 近期消息 + 基础系统提示”的近似 token 数，详情标明“估算”；该值不包含全部动态提示及工具 schema，不是供应商 usage。实际累计输入/输出统计保持不变，下一轮回复恢复使用真实 usage。

再次反馈后的补充：会话 checkpoint 为空时，先在内存中从展示库恢复正文与工具记录，摘要成功后同时写回；不能将 checkpoint 为空等同于没有旧历史。旧消息缺少 `turn_id` 时生成稳定标识，后续聊天续用已保存摘要。跳过也返回有效上下文估算，并用 `reason` 区分已压缩、只有近期内容或完全空历史。所有状态均绑定点击时的消息位置，包含跳过和失败；继续发送时保留在原消息后，不固定于消息列表底部。

主流程仍为：**检查并锁定会话 → 读取 → 摘要 → 保存 → 返回结果**，上述边界落实为各步骤中的判断和错误处理。

### 5.3 已验证的可行性

2026-10-26，使用当前安装的 DeepAgents 0.7.28、LangGraph 1.2.16、项目摘要中间件和官方 `AsyncSqliteSaver` 做了临时离线实验。模型复用 [test_compression_snapshots.py](../../tests/agent/test_compression_snapshots.py) 的 `Recorder`，数据写入临时目录，没有调用线上模型或修改业务会话。

| 验证项 | 结果 |
| --- | --- |
| 读取并手动摘要 | 原始 51 条，摘要覆盖前 45 条，有效上下文变成 1 条摘要 + 6 条近期消息 |
| 手动阶段模型调用 | 只调用摘要模型，没有额外生成主模型回答 |
| 保存状态 | 创建新 checkpoint，原始 51 条消息完整保留，未留下待执行任务 |
| 持久化恢复 | 关闭并重新打开 SQLite、重新建图后仍可读取摘要状态 |
| 下一轮复用 | 下一轮实际模型输入包含摘要，无须再次压缩即可继续 |

该实验验证了核心状态链路可实现，不等于业务接口已完成，也不评价真实模型摘要质量。正式接入时应将“手动摘要 → checkpoint 保存 → 下一轮复用”补为回归测试，并验证会话隔离、并发互斥、失败不覆盖旧状态及真实模型输入预算。

## 7. 验收

1. 输入 `/` 能看到“指令 → 压缩”，点击或 Enter 后立即执行，原技能选择正常。
2. 压缩期间有加载提示，重复点击或同会话聊天不会并发执行。
3. 成功后下一轮实际使用新摘要，原聊天记录保留，不多出聊天消息。
4. 没有旧内容时正确跳过，失败时原上下文仍可继续使用。
5. 两版前端与 AI 侧边栏都能完成上述流程。
