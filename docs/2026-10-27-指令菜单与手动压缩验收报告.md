## 2. 关键行为与接口

| 场景 | 验收行为 |
| --- | --- |
| 指令菜单 | 指令先于技能；支持鼠标、方向键和 Enter，兼容中文输入法；仅移除当前 slash 查询，保留草稿、附件和技能；技能加载失败仍可用。 |
| 可用性与状态 | 空会话、生成中、待审批、加载中及旧 thread 模式禁用；按会话维护状态，主聊天与侧边栏共享忙碌状态，其他会话可独立操作。 |
| 提示位置 | 进行中、成功、跳过和失败均固定在点击时的消息位置；后续回复不会把旧提示推到列表末尾。成功/跳过持久化，失败保留本机记录。 |
| 占用显示 | 成功或跳过均刷新有效上下文估算，明确标注“估算”；不改写真实累计 usage，后续真实调用数据接替估算。 |
| 模型选择 | 使用当前模型配置 key 解析摘要模型与窗口；临时切换摘要模型保留缓存专家代理的提示词和工具装配。 |

接口：`POST /agent/sessions/{session_id}/context/compact`，请求体为 `{"model": "模型配置key或null"}`。JWT 身份与归属校验先于代理和状态访问；前端通过 `context_compaction_enabled` 判断部署能力。

| 结果 | 响应 |
| --- | --- |
| 成功 / 无需压缩 | HTTP 200，`status=compacted/skipped`；返回估算和操作记录。跳过原因包括 `already_compacted/recent_only/empty_history`。 |
| 能力关闭 / 旧 thread 模式 | HTTP 400。 |
| 同会话忙碌 / 待审批 | HTTP 409。 |
| 异常 / 超时 | HTTP 500 / 504；认证与归属错误沿用现有契约。 |

接口等待摘要及保存后返回 JSON，服务端超时 300 秒，前端等待 330 秒。

## 3. 持久化与并发重点

- 从 checkpoint 应用已有摘要事件，按“有效历史”继续压缩；复用已有分块摘要器。仅剩旧摘要可切走时跳过，不重复调用模型。
- 旧会话无 checkpoint 时，从展示历史恢复消息与工具记录；归档、摘要成功后一次保存恢复消息与摘要事件。稳定消息 ID 保证下一轮继续该 thread，避免重新灌入全部历史。
- 使用 `aget_state()` / `aupdate_state()` 保存摘要事件、归档标识和展示记录，保留原始 `messages`；保存后回读校验，并确认没有挂起节点或审批。
- 聊天准备、审批恢复和压缩共用进程内会话租约及数据库流锁；客户端断开后，后台 SSE 任务完成才释放租约。拒绝、异常和超时均清理持锁状态。
